**Agile development** is a flexible and iterative approach to software development that focuses on:
- **Customer collaboration**
- **Quick delivery of working software**
- **Adaptability to change**
- **Continuous improvement**

Instead of planning everything up front and delivering a final product at the end (as in the traditional **Waterfall model**), Agile breaks the project into **small, manageable chunks** called **iterations** or **sprints** (typically 1–4 weeks).


## 💡 What is Extreme Programming (XP)?

**Extreme Programming (XP)** is an **Agile software development methodology** that focuses on:
- **High-quality software**
- **Responsiveness to changing customer needs**
- **Frequent releases**

## 🔁 Key Practices in XP

### 1. **Test-Driven Development (TDD)**

Write tests **before** writing code. This ensures that code does exactly what it needs to do and nothing more.

### 2. **Pair Programming**

Two developers work together at one computer — one writes the code, the other reviews it in real-time. This boosts code quality and team knowledge.

### 3. **Continuous Integration**

Code is integrated and tested **frequently** (often several times a day) to catch problems early.

### 4. **Refactoring**

Continuously improve the design of existing code without changing its behavior, keeping it clean and maintainable.

### 5. **Small Releases**

Release working software **frequently**, sometimes even daily, to get fast feedback from users.

### 6. **Customer Involvement**

A **real customer** (or representative) is part of the development team and gives daily feedback on features and priorities.

### 7. **Collective Code Ownership**

Everyone on the team can improve any part of the code at any time — no silos or “my code” attitude.

### 8. **Sustainable Pace**

Work at a steady, **non-exhausting** pace to avoid burnout (often called the “40-hour week” rule).

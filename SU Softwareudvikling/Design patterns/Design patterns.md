# What and why

Design patterns reduce cognitive load. Frees working memory.

Similar solutions for similar problems. Generalized solutions must be specified to the specific problem. You shorten development time, improve quality, intelligibility and standardize software. There are class related patterns (**static**) and object related patterns (**dynamic/runtime**).

* Structural connection
* Interaction patterns
* Creation of [[Terminology#Objects|objects]] (e.g. singleton pattern)

Description of patterns are: 
1) information about the purpose, 
2) what is the scope - what is not covered, 
3) description of structure and behaviour. 

The latter is represented by [[UML Basics#UML Basics|UML diagrams]].
Design patterns are not to be followed strictly, but are only *ideas*

![[Pasted image 20250311140121.png]]

• All design patterns have been derived from experience. 
• Design patterns provide appropriate solutions for recurring problems. 
• Some design patterns are supported in standard libraries. 
• Design patterns can be flexibly implemented in various ways. 
• Design patterns provide a common vocabulary for developers. 
• Design patterns can be combined with each other Example: 
	[[Observer]] iterates over the observed objects.
